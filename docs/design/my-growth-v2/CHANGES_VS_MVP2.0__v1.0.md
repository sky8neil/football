# 「我的」页面对照 MVP 2.0 改动说明

版本：v1.0　｜　基线：`docs/MVP__v2.0.md`　｜　设计参照：已选定的 `b-emblem.html` 与有历史赛季分支 `b-emblem-career.html`

## 结论摘要

- 页面主等级改为生涯等级，等级与称号严格按 `level_v3.0` 的 Lv.1–Lv.6 固定映射；本赛季等级作为独立范围展示，不与生涯等级混称。
- 移除旧八级、旧称号、基于分差的升级提示和所有等级进度环／进度条。只保留可由有效预测场次直接计算的评级与实力榜门槛提示。
- 移除所有准确率百分比、胜平负命中率及其汇总展示；等级与成长卡片不展示收缩场均分、`S`、`B` 或定级阈值。`n` 与「预言指数」仅按规范出现在实力榜区域。
- 榜单入口调整为本周榜、生涯榜、实力榜，并提供全站／我的群范围；榜单自身前 20 名、每页 10 条，「我的名次」遵循名次上限与百分位规则。
- 生涯积分继续作为独立成长数据展示；积分与解锁的后台关系不转译成前端解锁进度、奖励文案或装扮预览。

## 等级规则与页面口径

页面只渲染等级结果和确定的场次门槛，不呈现计算过程。`level_v3.0` 的评级逻辑为收缩场均分与累计积分双条件：评估窗口最多取最近 300 场、730 天内有效预测，`s=(S+68)/(n+40)`；生涯 `B=career_points`，赛季 `B=该等级赛季积分`。判定用整数交叉乘法，不用展示值比较。

| 当前等级 | 升级条件 | 保级线 |
|---|---|---|
| Lv.1 青训新人 | 有效预测累计达到 20 场即升 Lv.2 | 不降级 |
| Lv.2 潜力新星 | `s≥1.80` 且 `B≥80`，升 Lv.3 | 不降级 |
| Lv.3 崭露头角 | `s≥1.95` 且 `B≥170`，升 Lv.4 | `s≥1.70` |
| Lv.4 坐稳主力 | `s≥2.15` 且 `B≥380`，升 Lv.5 | `s≥1.85` |
| Lv.5 球队核心 | `s≥2.35` 且 `B≥630`，升 Lv.6 | `s≥2.05` |
| Lv.6 顶级球星 | 最高级，无升级 | `s≥2.25` |

Lv.2–Lv.6 的升级须同时满足收缩场均分线和目标等级 B 线；每次周评估最多升／降一级。Lv.3 及以上连续两次周评估低于当前保级线才降一级；全局保护期内不累计降级次数。每周一 10:00（北京时间）评估；首次正式结算不触发即时评估。赛果修正完成后，用本周周评估前状态重算并替换本周结论，不额外叠加一次升级／降级。`best_level` 只增不减。

等级赛季按北京时间每年 7 月 1 日 00:00 开始、次年 7 月 1 日 00:00 结束；跨联赛统计，不等同任一联赛赛季。赛季结束后的第一次周评估为最终评估，之后冻结该赛季等级；冻结后的历史赛果修正只更新积分与命中统计，不改等级。

## 三份模板的组织差异

| 模板 | 组织方式 | 适用讨论点 |
|---|---|---|
| `v2-a.html` | 延续徽章视觉，但以生涯主等级开场；成长数据、周评估和「我的名次」依次展开 | 最接近已选 `b-emblem` 的迁移方案 |
| `v2-b.html` | 仪表盘式先展示生涯积分，再并列生涯／赛季等级与场次门槛；榜单按行压缩 | 更适合未评级用户，突出确定的场次门槛而非升级分差 |
| `v2-c.html` | 以等级赛季和指定轮次分享数据为主轴，三榜与群范围作为次级入口 | 评估分享入口是否应进入「我的」首页；分享卡本身仍待视觉确认 |

三份模板使用一致的模拟老用户口径：生涯积分 300（0／3／12 分规则可组成）、132 场、2 次精确命中；评估窗口 96 场、窗口分 192，对应实力榜展示值 1.91。生涯 Lv.3、历史最高 Lv.4；当前等级赛季 `2026_2027` 为 Lv.2、58 场。分享示例选英超 `2026_2027` 第 `05` 轮：10 场、2 次精确命中、33 分（2×12＋3×3）。榜单位置样例为本周榜第 8、生涯榜第 36／286（前 13%）、实力榜第 18；`v2-b.html` 的新手样例为本周榜第 16、生涯榜第 22／24（前 92%）、实力窗口 12 场。`v2-b.html` 另用未评级样例说明场次门槛：12 场、12 分、1 次精确命中，评级还差 8 场、实力榜还差 38 场。

## 视觉与离线约束

- 继续使用 V1 球场背景与雾白玻璃卡、V1 绿／薄荷／中性色、低对比绿色阴影和既有圆角；玻璃模糊只柔化背景，卡面白底负责文字可读性。
- 字号只用既有 8 档 `18/20/22/24/26/30/32/36rpx`，375px 画布上最大 18px；使用系统字体栈，不加载网络字体。
- 间距与圆角沿用 `design-tokens.wxss`。每个 HTML 均内嵌 token CSS 与原始 `home-pitch-bg.webp` data URI；不请求外部图片、字体、脚本或样式，不依赖本地相对资源。
- 图标使用内联 SVG／CSS，不新增图像文件；不生成截图。静态按钮只显示说明 toast。

## 待确认

1. 三种信息组织方案中，最终采用哪一种作为 MVP「我的」页主结构。
2. 资料头像的真实字段、素材来源与缺省态；当前规范的 `/profile/me` 不返回头像资源。
3. `favorite_team_id` 对应球队名称／队徽由哪个前端数据源解析；预测记录 API 也只冻结球队 ID，名称嵌套形状为 `SPEC_GAP`。
4. 是否在「我的」页保留「最近预测」列表及其排序／截断数量；`/predictions/me` 返回分页数据，但页面模块本身未冻结。
5. 「我的群」范围的默认群选择、无群空态、建群／加入群入口布局；群名规则与群榜排序已由 MVP 冻结，具体页面交互未冻结。
6. 是否在本人页展示 `is_former_top` 派生提示；该字段仅私有接口可选，公开资料不可见，且不是独立称号。
7. 分享卡的最终视觉构成、联赛／赛季／轮次选择入口和分享动作；当前规范只冻结分享数据及请求参数，不冻结前端渲染。
