- 日期：2026-11-17。
- 状态：范围已确认，供后续开发使用；本次交付仅编写文档，不代表功能已实施或复测通过。
- 适用基线：本地仓库 `01fee09`，与用户提供的测试报告版本一致。
- 对应开发文档：[MINIPROGRAM_UX_DEV_PLAN__v1.0.md](MINIPROGRAM_UX_DEV_PLAN__v1.0.md)。

## 1. 目标与范围

首页首先要让用户一眼认出“谁和谁踢”。所有面向用户的球队名强制使用中文；逐队上网查中国大陆网站使用的简体中文名；两个不同网站使用同一名称即定名，不使用大模型翻译。未满足条件的单独列出，不编造、不静默回退英文，也不以“主队/客队”替代球队身份。

按以下顺序推进：

1. **先修识别和理解**：中文队名及完整对阵、日期计数、轮次单位、比赛与预测状态、等级解释、榜单空态承诺和重复文案（联赛标签 UX-05 本轮忽略，见第 3 节）。
2. **再核查数据展示**：历史预测缺队名、近期与更早记录的范围、领域不变量导致整页失败、榜单与收官数据的口径。
3. **最后完成本轮视觉及补测**：强化收官按钮、补解锁空态、增加历史赛季入口，并复核前两阶段相关页面。

**明确只记录、本轮不做**：降低背景干扰、窄屏布局专项、断网与重试注入专项、列表滚动到底专项。不得用“统一视觉并补测”扩大到这四项。

UX-06 统一文案与约束：

- 积分不足：“评估积分 474 / 630，还差 156 分”。此处为最近一次评估时点的累计 B 分，不能用当前生涯累计积分替代。
- 积分已够：“上次评估积分已达门槛，升级还需满足表现条件，以每周评估结果为准”。
- 本轮不展示或验收“已满足升级条件，等待每周评估”，不为此扩展接口。
- 满级：“已达最高等级 · 顶级球星”，展示当前评估积分，去掉“升级进度”和无目标进度条，不显示 `726 / —`。

- 保留规则：“表现与积分需同时达线，每周一 10:00（北京时间）评估，达线不即时升级，每次最多升一级。”等级数值以服务端为准，称号沿用现有小程序映射。

## 5. 球队中文命名规则

1. 以 `league_id + team_id` 识别球队，保留原始供应商名称、原始 ID、赛季及已有队徽关联；中文只用于展示，不能改写外部供应商匹配依据。
2. 对所有英文球队名上网搜索，以中国大陆网站实际显示的简体中文名为依据；**两个不同网站使用同一球队名即可定名**。不使用大模型翻译或自行音译。附录 A 为已按此规则完成的首轮定名结果。运行时不调用模型或搜索服务。
3. 一个球队一个规范中文展示名；同队不同外文别名归到同一 ID。历史更名或二队、青年队、同城同名等不能仅靠字符串合并。
4. 每队留存原始名、最终简体中文名、两个以上不同网站名称及各自 URL、页面标题、查询日期，明细见 [TEAM_NAME_EVIDENCE__v1.0.md](TEAM_NAME_EVIDENCE__v1.0.md)。不同页面或子域名仍属于同一网站时只计一个；必须核对确为同一球队，不能混入同城球队或青年队。球队 ID 在实施时按 `league_id + team_id` 回填。
5. 简称与全称并存时按多数站写法定名：曼联、皇家马德里、托特纳姆热刺、拜仁慕尼黑、马德里竞技、皇家贝蒂斯、纽卡斯尔联、诺丁汉森林、布伦特福德、阿斯顿维拉、瓦伦西亚、伊普斯维奇、弗罗西诺内、云达不来梅、莱比锡红牛、浙江队、河南队。少数站的另一写法登记为别名，不用于展示。
